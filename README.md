# geon-claude-plugins

KMGeon의 개인 Claude Code 플러그인 마켓플레이스.

## 설치

```
/plugin marketplace add KMGeon/geon-claude-plugins
/plugin install deep-workflow@geon-claude-plugins
/plugin install mem0-self@geon-claude-plugins
```

## 플러그인

[deep-workflow](plugins/deep-workflow) 하나에 스킬 두 개가 들어 있습니다. 각각 따로 불러도 되고, 인터뷰가 끝나면 빌드로 자동으로 이어집니다.

| 스킬 | 설명 |
|:---|:---|
| `/deep-interview` | 코드 작업 전 요구사항 인터뷰. 한 번에 한 질문, 코드가 계산하는 모호도, 스펙 저장 후 deep-goal 또는 deep-build로 넘김 |
| `/deep-goal` | 스펙의 완료 기준을 Claude Code `/goal` 조건 한 줄로 바꿔 줌. 사용자가 붙여 넣으면 조건 충족까지 세션이 계속 구현. 작고 분명한 스펙용 |
| `/deep-build` | 스펙을 받아 설계 → 계획 → 검토 → 구현 → 완료 판정까지 사람 승인 없이 진행. 계획은 고정 항목·완료 기준이 모두 연결돼야 저장되고, 작업은 코드가 실행한 테스트가 통과해야 끝남 |

## deep-interview 사용법

```
/deep-interview [--quick|--deep] <아이디어>
```

1. 기준값을 정하고(기본 20%, `--quick` 35%, `--deep` 5%) 큰 덩어리를 먼저 확정합니다 (Round 0).
2. 가장 흐릿한 부분을 골라 한 번에 한 질문씩 묻습니다.
3. 답마다 Claude가 체크리스트(예+근거 / 아니오)에 답하고, **코드가** 모호도와 최저선을 계산해 점수표로 보여줍니다.
4. 기준 아래로 내려가면 한 번 더 의심하고, 한 문장으로 맞춰 본 뒤 스펙을 `.deep-interview/specs/`에 저장합니다.
5. 기준을 통과한 스펙은 `deep-goal`(`/goal`로 구현) 또는 `deep-build`(설계·계획부터)로 넘어갑니다. `--goal`/`--build` 인자가 없으면 한 번 묻고, 조기 종료 스펙도 한 번 묻습니다.

## deep-build 사용법

```
/deep-build .deep-interview/specs/deep-interview-<주제>.md
```

1. 스펙에서 고정 항목 ID와 완료 기준 ID(AC-1…)를 뽑습니다. 인터뷰 기록이 있으면 빠진 고정 항목과 조기 종료 여부를 대조합니다.
2. 설계 문서를 씁니다. 시퀀스·상태·ERD·API 네 절이 모두 있어야 하고, 해당 없으면 "생략: 이유" 한 줄을 둡니다.
3. 작업 목록을 만듭니다. 모든 고정 항목과 완료 기준에 담당 작업이 있고, 작업마다 테스트 명령, 완료 기준마다 증거 명령이 있어야 코드가 계획 파일을 씁니다. 의존이 순환하면 거부합니다.
4. 계획을 쓰지 않은 새 에이전트가 스펙·설계·계획(테스트·증거 명령이 진짜인지 포함)을 대조합니다. 검토 3회 안에 통과해야 하고, 넘으면 멈춥니다.
5. 구현: 작업 3개 이하면 한 세션이, 4개 이상이면 작업별 구현 에이전트 + 리뷰 에이전트가 만듭니다. 작업은 **계획에 고정된 테스트 명령을 코드가 직접 실행**해 통과해야 끝나고, 3회 실패하면 전체를 멈춥니다.
6. 완료 판정: 계획에 고정된 증거 명령을 완료 기준(AC)마다 코드가 실행하고, 새 에이전트가 AC별 판정과 함께 전체를 스펙과 대조해 `pass`하면 끝납니다. `revise`면 지적된 작업을 다시 열어 테스트부터 다시 통과시킵니다. 커밋은 자동으로 하지 않고 묻습니다.

## deep-goal 사용법

```
/deep-goal .deep-interview/specs/deep-interview-<주제>.md [--test-cmd "npm test"]
```

1. 코드가 스펙의 완료 기준·지킬 조건·하지 않을 것을 읽어 `.deep-interview/goals/<주제>.md`와 `/goal` 조건 한 줄을 만듭니다. 조건은 기준마다 자동 테스트와 실제 실행 출력(종료 코드 0)을 요구하고, 테스트를 약하게 만들어 통과시키는 것을 금합니다.
2. 보여준 `/goal …` 한 줄을 채팅에 붙여 넣습니다. Claude Code의 `/goal`은 세션 Stop 훅이라, 평가자가 매 턴 끝에 조건을 판정하고 충족될 때까지 세션이 계속 일합니다. (`/goal`은 Claude Code 계정 기능 플래그로 켜집니다. `/goal 테스트`를 쳐서 "Goal set"이 뜨면 켜진 것입니다.)
3. 끝나면 변경 목록과 기준별 테스트 명령을 보여주고 커밋 여부를 묻습니다. 자동 커밋은 하지 않습니다.

deep-build와의 차이: deep-build는 코드가 증거 명령을 실행해 완료를 판정하고, deep-goal은 Claude Code 평가자(모델)가 조건 문장을 읽고 판정합니다. 큰 스펙은 deep-build, 작고 분명한 스펙은 deep-goal이 맞습니다.

## 코드가 지켜 주는 것

| 장치 | 하는 일 |
|:---|:---|
| 코드 수정 차단 | 인터뷰 중에는 그 세션의 소스 수정과 쓰기 명령을 막음. 세션 → 루트 색인(`~/.claude/deep-workflow/sessions/`)을 보므로 `cd`로 다른 저장소에 가도 풀리지 않음 |
| 답 원문 기록 | 선택지 창 답과 채팅 메시지를 `answers.jsonl`에 그대로 남김 |
| 모호도 계산 | 체크리스트 답으로 점수를 세고, 최저선(뒤집힌 사실, 빈 덩어리, AI 대리 답)을 적용 |
| 스펙 저장 조건 | 기록이 없거나, 기준 미달이거나, 마지막 사용자 답이 선택지 창의 `네, 이대로`가 아니면 저장을 막음. 범위 확정(`scope`)도 `맞아요` 선택이 있어야 함. 채팅 답·되물음은 확인으로 세지 않음 |
| 스펙 대조 | 빌드 시작 때 인터뷰 기록과 대조해 빠진 고정 항목·조기 종료를 잡음 |
| 계획 저장 조건 | 모든 고정 항목·완료 기준에 담당 작업이 있고, 테스트·증거 명령이 있고, 의존이 순환하지 않아야 계획 파일을 씀 |
| 작업 완료 판정 | 계획에 고정된 테스트 명령을 코드가 실행해 종료 코드 0일 때만 완료. 명령은 `amend`로만 바꿀 수 있음(기록 남음). 작업당 3회, 검토·리뷰 3회, verify 3회 제한 |
| 완료 기준 증거 | 계획에 고정된 증거 명령을 AC마다 코드가 실행, 전부 통과해야 최종 리뷰로 넘어감. 최종 리뷰는 AC별 판정이 다 있어야 하고 fail이 있으면 pass 불가 |
| 다시 열기 | 최종 리뷰 revise면 지적된 작업과 그에 의존하는 작업을 코드가 다시 열어 테스트부터 다시 통과시킴 |
| 설계 고정 | 등록한 설계 문서가 바뀌면 구현을 시작할 수 없음. 다시 등록하고 검토를 다시 받음 |

상태 파일(`.deep-interview/sessions/`, `plans/`, `builds/`)은 직접 고칠 수 없고 상태 명령으로만 바뀝니다. 셸 명령으로 우회하는 것까지 막지는 않습니다(받아들인 위험).
기록은 `.deep-interview/sessions/<세션>/`(상태, 답 원문)에, 결과는 `.deep-interview/specs/`에 남습니다.
설계 근거(이 플러그인을 딥 인터뷰로 설계한 기록)는 [docs/design-record.md](docs/design-record.md)에 있습니다.

## mem0-self

[mem0-self](plugins/mem0-self)는 Mem0 공식 Claude Code 플러그인을 self-host Mem0 서버용으로 포크한 것입니다. 설치 설정과 공식 플러그인과 다른 점은 플러그인 README에 있습니다.

node --test plugins/deep-workflow/tests/*.test.mjs
