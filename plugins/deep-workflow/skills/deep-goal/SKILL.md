# 딥 골

딥 인터뷰가 "무엇을, 왜"를 정했다면, 여기서는 그것을 Claude Code의 `/goal`이 읽을 **조건 한 문장**으로 바꾸고 그 목표로 구현한다. 설계·계획 단계 없이 목표와 증거만 고정한다. `/goal`은 세션 Stop 훅이라, 조건이 충족될 때까지 세션이 끝나지 않는다.

deep-build와 다른 점은 완료 판정 주체다. deep-build는 코드가 증거 명령을 실행해 판정하고, `/goal`은 Claude Code의 평가자(모델)가 조건 문장과 대화 기록을 읽고 판정한다. 그래서 조건에는 **실행한 테스트 명령과 종료 코드 0 출력**을 요구하는 말이 들어가고, 그것을 코드가 만든다.

## 명령

```
node "${CLAUDE_SKILL_DIR}/scripts/goal.mjs" condition --spec <스펙 경로> [--force] [--test-cmd "<명령>"]
```

| 결과 필드 | 뜻 |
|:---|:---|
| `goal_path` | 목표 파일 `.deep-interview/goals/<slug>.md`. 완료 기준, 고정 항목, 경계, 조건 문장, 진행 메모 |
| `goal_command` | 사용자가 붙여 넣을 `/goal <조건>` 한 줄 |
| `form` | `full`(기준 본문 포함) 또는 `short`(한도 4000자를 넘어 파일 참조로 줄임) |

`"ok": false`면 `error`를 해결한다. 조기 종료 스펙이면 사용자에게 남은 빈 곳을 보여주고 한 번 물은 뒤에만 `--force`.

## 흐름

### 1. 조건 만들기

1. 스펙을 읽는다. 프로젝트의 전체 테스트 명령(`package.json`의 `test`, `pytest` 등)을 찾아 `--test-cmd`로 넣는다. 없으면 빼고, 기준별 테스트만 요구한다.
2. `condition`을 실행하고 `goal_path`를 읽어 완료 기준이 스펙과 같은지 눈으로 확인한다.

### 2. `/goal` 걸기

스킬은 내장 슬래시 명령을 직접 부를 수 없다. 둘 중 하나로 한다.

| 상황 | 할 일 |
|:---|:---|
| 도구 목록에 `ProposeGoal`이 있다 | 그 도구로 `condition`을 그대로 제안한다. 사용자가 승인하면 목표가 걸린다 |
| 없다 (보통) | 아래처럼 `goal_command`를 코드 블록에 **그대로** 보여주고, 붙여 넣어 달라고 한 줄로 말한 뒤 멈춘다 |

> 목표 파일: `{goal_path}` (완료 기준 {n}개)
> 아래 한 줄을 채팅에 붙여 넣으면 목표가 걸리고, 충족될 때까지 제가 계속 구현합니다.
> ```
> /goal {condition}
> ```

조건 문장을 고쳐 쓰지 않는다. 평가자는 그 문장을 글자 그대로 읽으므로, 고치면 코드가 넣은 증거 요구가 빠질 수 있다.

### 3. 목표가 걸린 뒤

"Goal set: …"이 보이면 바로 시작한다. 묻지 않는다.

1. `goal_path`와 스펙을 읽는다. 기존 코드를 고치는 일이면 스펙의 "코드에서 확인한 것"에 적힌 파일을 다시 본다.
2. 완료 기준 하나씩: 그 기준을 검사하는 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다. 테스트 명령과 결과를 목표 파일의 "진행 메모"에 적는다.
3. 매 턴 끝에는 그 턴에 통과시킨 테스트 명령을 **실제로 실행한 출력**이 대화에 남게 한다. 평가자는 말이 아니라 출력을 본다.
4. 전부 끝났다고 보이면 `--test-cmd`의 전체 테스트를 한 번 더 돌리고, 목표 파일의 완료 기준 체크를 `[x]`로 바꾼다. 평가자가 "not met"으로 되돌리면 `Last check` 이유를 읽고 그 빈 곳만 메운다.
5. 사람만 풀 수 있는 막힘(권한, 외부 결정)이면 막힌 이유를 한 줄로 쓰고 사용자에게 `/goal clear`를 안내한다. 추측으로 메우지 않는다.

## 지키는 규칙

1. **스펙이 기준이다.** 조건·목표 파일·코드가 스펙과 충돌하면 스펙을 따른다.
2. **조건 문장은 코드가 만든 것만 쓴다.** 손으로 줄이거나 바꾸지 않는다.
3. **테스트를 지우거나 건너뛰게 만들어서 통과시키지 않는다.** 그렇게 해야만 통과한다면 멈추고 사용자에게 알린다.
4. **"하지 않을 것"은 만들지 않는다.** 목표를 빨리 끝내려고 범위를 줄이지도 않는다.
5. **커밋·푸시는 하지 않는다.** 끝나면 `git diff --stat`과 기준별 테스트 명령 표를 보여주고 AskUserQuestion으로 커밋 여부를 묻는다: `커밋하기`, `변경만 두기`, `되돌리기`.
6. **글은 사용자의 CLAUDE.md 규칙**을 따른다: 한국어, 결론 먼저, 표, 짧은 문장.
