## 무엇을 만드나
코드 작업을 시작하기 전에 사용자와 일대일로 인터뷰해서 요구사항의 빈 곳을 메우는 Claude Code 플러그인. 질문은 하나씩, 가장 흐릿한 곳부터 묻고, 점수로 진행 정도를 보여주며, 끝나면 스펙 파일 하나를 남기고 멈춘다.

| 덩어리 | 상태 | 설명 | 어디까지 정했나 |
|:---|:---:|:---|:---|
| 1 질문 방식 | ✅ | 몇 개씩, 어떤 형태로 묻는지 | 하나씩, 추천 선택지 + 자유 입력, 코드 먼저 읽기, 점검은 혼자 세 관점 |
| 2 끝내는 기준 | ✅ | 언제 충분히 명확하다고 보는지 | 모호도 점수, 기본 20%, 시작할 때 조정 |
| 3 결과물 | ✅ | 무엇을 어디에 남기는지 | 전체 기록을 담은 스펙, `.deep-interview/specs/` |
| 4 그다음 단계 | ✅ | 스펙 이후 흐름 | 스펙 저장 후 멈춤 |
| 5 무건님 형식 | ✅ | 출력 형식 | CLAUDE.md 규칙, 매 라운드 점수표만 표시 |

**고정 항목**
- `원칙:인터뷰` — 전제를 꺼내 확인하기, 사실은 직접 찾고 결정만 묻기, 쉬운 일은 인터뷰하지 않기
- `조건:기본기능만` — 직접 만든 코드(CLI, 훅) 없이 Claude Code 기본 기능만 사용 → **일부 뒤집힘 (f12):** 코드 수정 차단 훅과 시작/종료 스크립트는 예외
- `상황:코드작업전` — 코드 작업 전에 쓴다
- `결과물:스펙` — 결과물은 스펙 문서 하나

## 경계
**지킬 조건**
- 직접 만든 코드: 상태 명령(`scripts/interview.mjs`, `scripts/state.mjs`), 가드 훅(`hooks/guard.mjs`, `hooks/bash-check.mjs`), 답 기록 훅(`hooks/record-answer.mjs`). 질문 고르기, 체크리스트 답, 스펙 쓰기는 SKILL.md와 기본 도구로 한다.
- 화면의 모호도 숫자는 반드시 `record` 결과에서 가져온다.
- 한 번에 질문 하나. 추천 선택지를 맨 앞에 두고, 자유 입력은 도구의 기본 입력 칸으로 받는다.
- 질문 전에 관련 코드를 먼저 읽는다. 코드에서 알 수 있는 건 묻지 않는다.
- 사용자에게 보이는 글은 CLAUDE.md 규칙(한국어, 결론 먼저, 표, 짧은 문장)을 따른다.
- 매 라운드 화면에는 점수표와 덩어리 진행 줄만 보여준다.
- 인터뷰 중에는 코드를 고치지 않는다.

**하지 않을 것**
- 구현 계획 작성, 계획 검토, 구현 실행
- 플랜 모드 사용
- 별도 에이전트로 점검이나 대신 답하기 실행
- 스펙 본문 형식(6개 묶음, 고정 항목 포함 여부)을 코드로 검사하기 (저장 조건만 검사)
- 별도 채점 AI, temperature 설정 (최신 모델이 지원하지 않음)

**나중으로 미룬 것**
- 없음

**받아들인 위험** (2026-10-22 리스크 점검, f18)
코드 수정 차단은 AI가 실수로 코드를 고치는 것을 막는 장치이고, 일부러 우회하는 것까지 막지는 않는다. 아래는 알고 남겨 둔 것이다.
- Bash 우회: 셸 문법(`$'...'` 따옴표, zsh 확장), `git -c` 설정 주입, 환경 변수 앞붙이기, 읽기 명령의 쓰기·실행 옵션(`sed w`, `sort -o`, `tree -o`, `uniq`, `rg --pre`, `fd -x`, `git grep -O`), `>&파일`, 임시 폴더의 가짜 `scripts/interview.mjs`
- 검사하지 않는 도구: MCP 쓰기 도구 등 Edit/Write/MultiEdit/NotebookEdit/Bash 밖의 도구
- 차단이 풀리는 경우: 작업 위치가 프로젝트 밖일 때, 상태 파일이 깨지거나 다른 세션이 지웠을 때, 경로 대소문자를 바꿨을 때(macOS)
- 설계상 한계: 체크 "예"의 근거 진위, 아무 메시지나 "사용자 확인"으로 셈, AI가 `end --status cancelled`로 스스로 해제 가능, `record` 동시 실행 시 유실 가능

같은 점검에서 고친 것: 답 번복 시 그 라운드 체크도 되돌림, `--quick`/`--deep` 뒤 단어 삼킴, 잘못된 `--type`이 기존 기록만 보관하던 순서, 상위 폴더 `.deep-interview` 우선, 답 원문 커밋 방지(`.deep-interview/.gitignore`에 `sessions/`).

| 7 | 중간 → 막바지 | 삐딱하게, 줄여서 | 전체 형식 스펙은 매 라운드 기록이 필요하다 → Round 8 표시 방식 질문 |

**꺼내서 확인한 전제**
| 전제 | 어떻게 확인했나 | 결론 |
|:---|:---|:---|
| 결과물이 꼭 파일이어야 한다 | Round 2: 스펙 / 계획 / 대화 속 합의만 | 스펙 파일 |
| 기준값 5%가 적당하다 | Round 3 점검 → Round 4 | 20% |
| 인터뷰 뒤에 구현까지 이어져야 한다 | Round 6 | 스펙에서 멈춤 → 플랜 모드, 계획 검토 불필요 |
| 짧은 스펙이 낫다 (AI 추천) | Round 7 | 사용자는 전체 형식 선택 |

| 스펙은 커밋하는 폴더가 낫다 (AI 추천) | Round 10 | 사용자는 `.deep-interview/specs/` 선택 |

**내가 대신 정한 것**
- 파일 이름은 `deep-interview-<주제>.md`
- `.gitignore`는 건드리지 않는다
- "알아서 해" 답변은 별도 에이전트 없이 직접 처리하고, 확신이 높지 않으면 그 항목 점수 상한을 0.85로 둔다
- 기준값 조정 인자: `--quick` 35%, `--deep` 5%
- 최대 라운드는 30 (기본 기준값 20%에서는 보통 6~10라운드라 30이면 충분)
- 별도 에이전트용 프롬프트 파일은 지우고 필요한 내용만 SKILL.md에 넣는다
- SKILL.md는 문장, 예시, 스펙 양식을 모두 새로 쓰고, 스펙 양식은 담는 내용은 그대로 두고 6개 큰 묶음으로 다시 짰다
- 체크리스트 질문 12개(목표·제약·성공 기준·기존 코드 각 3개)의 문구
- 화면 모호도는 덩어리 평균으로 계산하고, 기준 통과는 모든 덩어리가 각각 기준 이하일 때만 인정한다. 처음엔 "가장 낮은 덩어리" 기준이었는데, 실제 테스트에서 빈 덩어리가 하나라도 있으면 모호도가 100%에서 움직이지 않아 진행이 안 보여서 바꿨다
- intent.md를 따로 두지 않은 이유: Anthropic이 문서를 나눈 건 역할이 다른 사람 사이의 인계 때문인데, 혼자 쓰는 경우엔 이득이 작고 두 문서가 서로 어긋날 위험만 생김. plan 단계를 붙이거나 여럿이 쓰게 되면 다시 검토
- 사용자 답이 "라운드 뒤에 왔는지"는 시각이 아니라 답 개수로 판단한다 (같은 밀리초에 기록돼도 정확하게)
- 정상 종료(`end`)도 스펙 저장과 같은 조건을 거친다. 사용자가 그만둘 때만 `--status cancelled`로 조건 없이 끝낸다
- deep-build 2단계에서 내가 정한 것: 구현 중 커밋·푸시는 하지 않고 끝나면 커밋 여부를 묻는다 (무건님 전역 규칙 "커밋은 시킬 때만"). 인터뷰에서 브랜치·커밋 처리는 정해지지 않았었다. 테스트 명령은 AI가 고르되 코드가 실행하고 종료 코드로만 판정한다. 에이전트 방식에서 리뷰 `revise`도 작업 실패 횟수로 센다. 최종 리뷰 `revise`면 증거를 무효로 돌려 verify부터 다시 한다. 명령 실행 제한 시간은 10분
- deep-build 1단계에서 내가 정한 것: 플러그인 이름 `deep-build`(2단계 구현까지 담을 이름). 완료 기준 ID는 스펙의 "다 됐다는 기준" 순서대로 AC-1… 로 코드가 붙인다. 설계 문서는 AI가 직접 쓰고 `design` 명령이 4개 절(시퀀스·상태·ERD·API)과 "생략: 이유"를 검사한다. 계획은 JSON으로 받아 코드가 연결을 검사하고 markdown을 쓴다(`plans/`, `builds/`는 훅이 직접 쓰기를 막음). 검토 에이전트는 `general-purpose`로 띄우고 JSON 판정을 `review` 명령이 기록한다. 검토 횟수 제한(3회)은 코드가 센다

## 코드와 개념

**코드에서 확인한 것**
- 기존 `plugins/deep-interview`에는 상태 CLI(`di.mjs`, `lib.mjs`)와 훅(`guard.mjs`, `bash-check.mjs`, `record-answer.mjs`)이 있었다. 이번 인터뷰 직전에 지웠다.
- 남은 파일: `SKILL.md`(다시 써야 함), `plugin.json`, `LICENSE`.
- Claude Code 스킬은 `$ARGUMENTS` 치환을 지원한다 (2.1.308에서 확인).

**개념 목록**
| 대상 | 성격 | 속성 | 관계 |
|:---|:---|:---|:---|
| 인터뷰 | 핵심 | 기준값, 현재 모호도, 라운드 목록 | 라운드 여러 개를 가지고, 스펙 하나를 만든다 |
| 덩어리 | 핵심 | 이름, 상태, 항목별 점수 | 인터뷰에 속하고, 질문의 대상이 된다 |
| 라운드 | 핵심 | 번호, 질문, 답, 점수 | 인터뷰에 속하고, 덩어리 하나를 겨냥한다 |
| 모호도 점수 | 보조 | 목표, 제약, 성공 기준, 최저선 | 라운드마다 계산된다 |
| 확정된 사실 | 보조 | 번호, 내용, 라운드, 상태 | 라운드에서 생긴다 |
| 세 관점 점검 | 보조 | 관점, 발견 | 구간이 바뀔 때 다음 질문에 반영된다 |
| 스펙 | 핵심 | 6개 묶음 | 인터뷰가 끝나면 저장된다 |
